# AI 챗봇 (고객 대응 자동화) — PRD (Product Requirements Document)

## 1. 프로젝트 개요
- **프로젝트명**: AI 고객 대응 챗봇
- **목적**: 고객 문의를 자동으로 분류하고 적절한 답변을 제공하여 고객 대응 효율성을 극대화하고, 상담원 업무 부담을 경감
- **대상 사용자**:
  - **1차 사용자**: 제품/서비스에 대해 문의하는 최종 고객
  - **2차 사용자**: 고객 문의를 모니터링하고 에스컬레이션된 문의를 처리하는 상담원
  - **3차 사용자**: 챗봇 운영 현황을 파악하고 답변 품질을 관리하는 관리자
- **핵심 가치**:
  - **24/7 즉시 응답**: 사람 없이도 고객이 언제든지 답변을 받을 수 있음
  - **정확한 분류**: AI 기반 문의 분류로 상담원 라우팅 정확도 향상
  - **학습 가능**: 누적된 대화 이력을 통해 답변 품질 개선 가능

---

## 2. 사용자 페르소나

### 페르소나 1: 최종 고객 (김민수)
- **역할**: 제품 구매 전 문의하는 일반 소비자
- **목표**: 제품 가격, 배송, 반품 정책 등을 빠르게 확인하고 싶음
- **불편점**:
  - 상담원 연결까지 긴 대기 시간
  - 영업 시간 외에는 문의할 방법이 없음
  - 간단한 질문에도 복잡한 절차를 거쳐야 함
- **기대사항**: 채팅창에 질문을 입력하면 즉시 답변을 받고 싶음

### 페르소나 2: 고객 상담원 (이지영)
- **역할**: 에스컬레이션된 복잡한 문의를 처리하는 전문 상담원
- **목표**: 단순 반복 문의는 챗봇이 처리하고, 본인은 고난도 문의에 집중
- **불편점**:
  - 같은 질문을 수십 번 반복 답변
  - 문의가 잘못 분류되어 처리 시간 증가
- **기대사항**:
  - 챗봇이 1차 필터링을 해주고, 본인에게는 정확히 분류된 문의만 전달되기를 바람
  - 고객의 이전 대화 이력을 즉시 확인 가능

### 페르소나 3: 운영 관리자 (박수진)
- **역할**: CS 팀 총괄, 챗봇 성과 모니터링
- **목표**: 챗봇 자동 해결률, 고객 만족도, 에스컬레이션 비율 파악
- **불편점**:
  - 챗봇이 잘못된 답변을 하는 경우를 놓침
  - 개선 포인트를 찾기 어려움
- **기대사항**:
  - 대시보드에서 주요 지표를 한눈에 확인
  - 문제가 되는 대화를 빠르게 찾아 답변 개선

## 4. 비기능 요구사항

### 성능
- **응답 속도**: AI 답변 생성 시간 3초 이내 (OpenAI API 호출 포함)
- **동시 접속**: 최소 100명의 동시 채팅 처리 가능
- **가용성**: 99% 이상 (월 기준)

### 보안
- **API 키 보호**: OpenAI API 키는 백엔드에서만 관리, 클라이언트 노출 금지
- **입력 검증**: XSS, SQL Injection 방지를 위한 입력 sanitization
- **개인정보 보호**:
  - 대화 내용에 포함된 개인정보(이름, 전화번호, 이메일)는 마스킹 후 로깅
  - 개인정보 보유 기간 준수 (1년 후 자동 삭제)
- **인증**: JWT 기반 인증 (선택적 로그인 지원)

### 확장성
- **수평 확장**: Docker 컨테이너 기반 배포, 로드 밸런서 지원 가능 구조
- **데이터베이스 파티셔닝**: 대화 이력이 증가해도 쿼리 성능 유지 (인덱싱 전략)

### 유지보수성
- **모니터링**:
  - OpenAI API 호출 성공률, 응답 시간 로깅
  - 에러 발생 시 알림 (재시도 실패, API 한도 초과 등)
- **로깅**: 구조화된 로그 (Winston/Pino), 레벨별 분리 (error/warn/info/debug)

## 5. 기술 제약조건

- **Frontend**: Next.js 14 (App Router), TypeScript, Tailwind CSS
- **Backend**: Express.js, TypeScript, Prisma ORM
- **Database**: PostgreSQL 16 (관계형 데이터 모델 필수)
- **AI**: OpenAI API (GPT-4 또는 GPT-3.5-turbo)
- **실시간 통신**: WebSocket (Socket.io 또는 native WebSocket)
- **캐싱**: Redis (세션, 자주 조회되는 FAQ 캐싱)
- **테스트**: Vitest (백엔드 단위 테스트), Playwright (E2E)
- **배포**: Docker 컨테이너

---

## 6. 범위 외 (Out of Scope)

- **음성 채팅**: 텍스트 기반만 지원, 음성 인식/TTS는 제외
- **멀티미디어 전송**: 이미지, 파일 첨부는 1차 버전에서 제외
- **소셜 로그인**: 이메일 기반 회원가입만 지원 (OAuth는 추후)
- **모바일 앱**: 웹 기반만 제공, 네이티브 앱은 제외
- **상담원 채팅 UI**: 에스컬레이션 알림만 제공, 상담원 전용 채팅 인터페이스는 제외
- **결제 통합**: 제품 추천은 가능하나 직접 결제는 불가

## 7. 성공 지표

### 정량 지표
- **자동 해결률**: 챗봇이 상담원 개입 없이 해결한 문의 비율 60% 이상
- **평균 응답 시간**: 고객 메시지 전송 후 첫 답변까지 5초 이내
- **문의 분류 정확도**: 에스컬레이션 문의의 잘못된 분류 비율 10% 이하
- **고객 만족도**: 대화 종료 후 긍정 피드백 비율 70% 이상
- **일일 활성 사용자**: 출시 1개월 내 100명 이상

### 정성 지표
- 고객이 "답변이 도움이 되었다"고 느낌
- 상담원이 "단순 문의가 줄었다"고 보고
- 관리자가 "대시보드에서 문제 지점을 쉽게 찾을 수 있다"고 평가

## 8. 제약 및 리스크

### 기술 리스크
- **OpenAI API 의존성**: API 장애 시 챗봇 전체 중단
  - **완화 방안**: 재시도 로직, 폴백 메시지 제공, API 헬스체크
- **Rate Limit**: OpenAI API 호출 한도 초과 가능
  - **완화 방안**: 요청 큐잉, Redis 기반 응답 캐싱, 호출량 모니터링
- **WebSocket 연결 불안정**: 네트워크 끊김 시 대화 유실
  - **완화 방안**: 자동 재연결, 미전송 메시지 로컬 저장

### 비즈니스 리스크
- **답변 품질**: AI가 부정확하거나 부적절한 답변을 할 수 있음
  - **완화 방안**: 프롬프트 엔지니어링, 답변 품질 모니터링, 관리자 검토 기능
- **개인정보 유출**: 고객 대화 내용 노출
  - **완화 방안**: 암호화 전송, 접근 권한 제어, 정기 보안 감사

---

## 9. 우선순위 결정 기준

- **Must**: MVP에 필수적인 기능 (없으면 서비스 불가)
- **Should**: 사용자 경험 향상에 중요하지만 우회 가능
- **Could**: 있으면 좋지만 출시 지연 시 제외 가능
